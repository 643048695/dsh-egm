# 缺陷清单格式（所有挑刺角色共用）

## 必须长这样

一行一条，`|` 分隔，四段：

```
级别 | 位置 | 问题 | 不改会怎样
```

- **级别**：`阻塞` / `建议` / `待确认`
- **位置**：`文件:行号`（必须是真实存在的文件与行），或 `[无代码依据]`
- **问题**：≤50 字，一句话说清哪儿不对
- **不改会怎样**：≤30 字，说**后果**，不要说「不够专业」「体验不好」

## 例子

```
阻塞 | docs/plan.md:18 | 增量判定只说「比对文件」没说比什么 | 改名后全量重传，备份变慢 10 倍
阻塞 | scripts/backup.sh:7 | 用了 rsync 但仓库没声明依赖 | 换台机器直接跑挂
建议 | docs/plan.md:33 | 没写临时文件谁来清 | 磁盘半年后涨满
待确认 | [无代码依据] | 「支持断点续传」是走 HTTP Range 还是自己记 offset | 实现方向完全相反，返工
```

## 硬规矩

1. **不许写「整体不错」「思路清晰」「建议进一步考虑」** —— 这些不是缺陷。
2. **不许编行号**。没打开过文件就写 `[无代码依据]`，否则这条作废。
3. **不可测的词不许出现**：友好、流畅、合理、尽量、稳定、优雅、更好。要说得出口径。
4. 每条 ≤50 字。写不下就说明你还没想清。
5. 总数 ≤500 字。超了就是你挑得不够狠，先砍掉最不重要的。
6. 挑不出问题就写一行：`无阻塞项`。**不许为了凑数编问题。**
7. 排序：阻塞在前，建议在后。同一级别里，按「不改会死得多惨」排。
