# 设计与代码漂移检查（DSH 适配版）

## 0. 这是什么

上游 `egm-drift-report`（`vendor/egm/skills/egm-drift-report/SKILL.md`）的工序适配版。
目标只有一个：找出「文档说了、代码里没做到 / 做成了别的样子」的地方。**只报差异，不夸做得好的部分。**

不需要派金鱼，也不需要许可；这是主会话的读文件 + 写报告工作。

## 1. 输入

- 一个目录（必需）：里面是要检查的设计文档或 README。没给就问「查哪个目录？」。
- 可选：只查某几份文档。

默认同时接受 `.md` 与 `.mdx`；跳过 `node_modules`、`.git`、构建产物目录。

## 2. 流程

### Step 1 列文档

列目录下的文档文件，按文件名排序，**逐份处理（串行）**：一次只读一份并立刻写出结论，避免一次吞太多内容。
先告诉用户要查几份、大概要多久；超过 10 份时建议先分批（每批 ≤10 份）并说明代价。

### Step 2 逐份分析

对每份文档：

1. **读懂意图**：它承诺了什么行为、提了哪些文件名/类名/函数/接口/配置项。
2. **定位源码**：按文档点名的路径去找；没写路径就用搜索（`ops_grep` / `ops_glob`）找类名、函数名、路由、配置键。
   找不到就记一条「文档点名的 X 在代码里找不到」——这本身就是漂移，不要跳过。
3. **读现状**：打开那些源文件读当前实现，不靠记忆、不靠文件名猜。
4. **比对**，只找这四类：
   - 缺失功能：文档描述的逻辑在代码里不存在；
   - 模型不完整：文档要求的字段/参数/表项，结构定义里没有；
   - 逻辑走捷径：该动态计算的地方写死常量、该走配置的写死分支；
   - 架构分歧：实现用了另一套模式/库/分层，与文档方案不一致。
5. **过滤**：只写差异。代码完全对得上就写 `No drift detected.`，不要列举「以下部分实现正确」。

### Step 3 写报告

追加写到 `.egm/classic/drift/<YYYY-MM-DD>_DRIFT_REPORT.md`（同一天多次运行就追加，不覆盖）。
格式照原版，严格两段：

```markdown
## <文档名>

- <具体差异 1>（`文件:行号`，文档依据：`§ 标题`）
- <具体差异 2>
```

对得上就一行 `No drift detected.`。
报告头写：检查目录、文档数、生成时间、检查方式（逐份串行、只读）、以及「本报告只列差异，不构成实现建议」。

多份文档共用一个根因时，在各节分别列，但末尾加一节「## 跨文档共性问题」把它们合起来说一次。

### Step 4 收尾

聊天里只报：报告路径、文档数、差异条数、最严重的 2–3 条一句话摘要。
不要贴报告全文，也不要在聊天里改代码。

## 3. 边界

- 只读：不改任何源码、不改被检查的文档；要改请用户另开任务。
- 不评价设计好坏：那是 `egm-classic-review` 的活；这里只问「代码有没有照做」。
- 文档没点名也没暗示的代码，不强行比对；记「未覆盖」而不是编差异。
- 找不到源文件时，先怀疑自己搜错（换关键词再搜一次），仍找不到才记为漂移，并写清搜过什么。

## 4. 与原版的差异

| 原版 | 这里 |
| --- | --- |
| 报告写当前目录 `{YYYY-MM-DD}_DRIFT_REPORT.md` | 写 `.egm/classic/drift/`，避免污染项目根 |
| 可一次吞多份文档 | 强制逐份串行，并先报数量与批次 |
| 无「未覆盖」要求 | 报告必须有未覆盖说明（没搜到/没读到的部分） |
